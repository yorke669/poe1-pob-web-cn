# 读属性方案设计

> 目标：在不改 PoB Lua 主逻辑的前提下，新增一个「读取当前构筑计算结果」的能力，要求
> ① 触发方便（便于测试）；② 结果在页面上展示出来，可一键复制出去二次加工。

## 1. 数据从哪来（PoB 侧已有结构，无需重算）

构筑加载/换装后，PoB 已把全部计算结果放进 `build.calcsTab.mainOutput`：

- `mainOutput.Life`、`mainOutput.EnergyShield`、`mainOutput.Armour` 等标量
- `mainOutput.SkillDPS` 是数组（每个技能的 DPS）
- `mainOutput.Minion[...]` 是召唤物属性

而 PoB 在 Calcs 面板真正**展示**的那批精选属性，已由 `build:SaveDB` 规范好，来源是（`Build.lua:427`）：

```lua
self.displayStats, self.minionDisplayStats, self.extraSaveStats = LoadModule("Modules/BuildDisplayStats")
```

`SaveDB` 遍历它们、从 `mainOutput` 取值，序列化为 `<PlayerStat stat=.. value=..>`（`Build.lua:1013-1051`）。

**设计取数策略**：复用这套精选列表，直接遍历 `build.displayStats` + `build.extraSaveStats`，按 `statData.stat`（+ `childStat`）从 `build.calcsTab.mainOutput` 取值。这样读出来就是 PoB 面板里那批关键属性，最贴近用户认知，也避免把 `mainOutput` 整个巨表丢出来。

- `build` 的取法（与 `boot.lua` 现有写法一致）：`mainObject.main.modes["BUILD"]`
- `GetMainObject()` 已在 C 层挂成 Lua 全局（`driver.c:113`），`boot.lua` 里直接用。

## 2. 返回值设计（JSON 文本）

本版本 PoB **没有 JSON 库**（全仓搜索 `json`/`Json` 0 命中），故在 `boot.lua` 内写一个**内联最小化序列化器**（仅处理 string/number/boolean/array/table，约 20 行），把精选属性输出为 JSON 字符串。

返回的 JSON 形态（key 用 `stat` 名，value 为数值或字符串）：

```json
{
  "Life": 5234,
  "EnergyShield": 120,
  "Armour": 1800,
  "SkillDPS": { "Toxic Rain": 1250000, "Caustic Arrow": 980000 },
  "FireResist": 75,
  "ColdResist": 75,
  "LightningResist": 75
}
```

- 默认只输出精选列表（轻量、好复制）。
- 可选扩展：加一个参数控制是否输出完整 `mainOutput`（用于深挖），本期不实现。

## 3. 触发方式（三层，优先方便测试）

| 层级 | 触发手段 | 用途 |
|---|---|---|
| **A. JS / Playwright（主测）** | 暴露 `driver.getBuildStats()` 到全局：`window.__POB__ = driver`（正常模式）/ `window.__POB_TEST__.getBuildStats`（测试模式，`run.ts:134` 同款） | DevTools 控制台 `await window.__POB__.getBuildStats()`，或 Playwright `page.evaluate` 调用，最利于自动化与脚本化测试 |
| **B. 覆盖层工具栏按钮（手点测）** | 在 driver 覆盖层（overlay）工具栏新增「📊 Stats」开关按钮，复用 Performance 按钮的机制 | 手动在页面上点一下即取数并弹面板 |
| **C. URL 参数自动触发（可选）** | `?autostats=1`：build 加载完成后自动取数并展示 | 演示/分享用，非必需 |

> 取数前无需重算：`loadBuildFromCode` 末尾已 `runCallback("OnFrame")` 触发 `calcsTab:BuildOutput()`（`Build.lua:677/1246`），`mainOutput` 已是最新。后续接「换装」接口后，换完需先触发一次重算再读（本期不涉及）。

## 4. 页面展示（可复制）

新增 React 覆盖层组件 `StatsOverlay`（参照 `PerformanceOverlay.tsx`），渲染条件为 `statsVisible`（参照 `performanceVisible`）：

- 容器设 `pointer-events: auto`（`PerformanceOverlay.tsx:49` 同款，覆盖层默认 `pointer-events: none`，`driver.ts:242`）；
- 主体一个可滚动 `<pre>` / `<textarea>` 显示 JSON 文本；
- 一个「Copy」按钮，复用现有 `ClipboardController`（`driver.ts:73`）写入剪贴板；
- 数据来源：组件通过 `onRequestStats` 回调 → `driver.ts` → `driverWorker.getBuildStats()`。

工具栏按钮与 `statsVisible` 状态挂在 `Driver` 类，机制与 `setPerformanceVisible`（`driver.ts:581`）完全对称。

## 6. 调用时序（读属性）

```
控制台/Playwright/按钮
   → driver.getBuildStats()                 (driver.ts)
   → driverWorker.getBuildStats()           (worker.ts, Comlink RPC)
   → cwrap("get_build_stats")               (worker.ts)
   → get_build_stats() [C]                  (driver.c)
   → lua getBuildStats()                    (boot.lua)
        → 遍历 build.displayStats/extraSaveStats
        → 读 build.calcsTab.mainOutput
        → 内联序列化器 → JSON 字符串
   → 字符串回传 → StatsOverlay 展示 + Copy
```
