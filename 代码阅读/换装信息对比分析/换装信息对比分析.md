# 换装信息对比分析

> 目标：确认能否通过接口「导入 POB 构筑 → 换一件装备 → 快速对比属性提升」。

## 架构速览

PoB 核心逻辑是上游 Lua 代码，本仓库把它编译进一个 **Wasm（Emscripten）驱动**（`packages/driver`）运行。分层（类比 Java/Node 生态）：

- `Lua 引擎 + 构筑数据` ≈ 领域内核（跑在 Wasm 里）
- `packages/driver/src/c/*.c` ≈ JNI 层，用 `EMSCRIPTEN_KEEPALIVE` 把内核少数函数暴露给 JS
- `packages/driver/src/js/worker.ts` 用 `cwrap` 把这些 C 函数包成 JS 调用
- `packages/driver/src/js/driver.ts` 的 `Driver` 类 ≈ public SDK，主线程经 Comlink 远程调 worker 里的 Wasm

**当前 JS 可见的内核接口面极薄**（`worker.ts:320` 的 `resolveImports`）：`init / start / load_build_from_code / get_build_code / on_frame / 键盘鼠标 / set_layer_visible / 剪贴板 / subscript`。

## 1. 导入构筑：CLI / HTTP / JS 哪种可行？

| 方式 | 结论 | 说明 |
|---|---|---|
| JS | ✅ 可行 | `driver.loadBuildFromCode(code)`（`driver.ts:425`） |
| CLI | ❌ 不行 | 驱动只能在浏览器跑（依赖 WebGL2 + `SharedArrayBuffer` 跨域隔离），无 headless CLI |
| HTTP | ❌ 不行 | `web` 包 `/api/*`（Wrangler）只是引擎自身的 CORS 代理 / KV / fetch，没有「POST 导入构筑」接口 |

JS 导入细节：
- 入口是 Lua 全局 `loadBuildFromCode`（`boot.lua:198`），把 `code` 塞进 app 内导入框并点导入：`importCodeIn:SetText(code)` + `importCodeMode.selIndex = 2` + `importCodeGo.onClick()`。
- `code` 接受**标准 POB 分享码（base64 长串）**，也接受**粘贴的 XML**（与 app 手动粘贴等价）。
- 反向导出：`driver.getBuildCode()`（`driver.ts:429`）→ Lua `getBuildCode`（`boot.lua:225`）返回 base64 分享码。
- 往返已验证：`packages/driver/test/e2e/driver.spec.mts:175` 用 `loadBuildFromCode` + `getBuildCode` 做了 round-trip 测试。

实操：用 Playwright/Puppeteer 开页面、实例化 `Driver`、调 `loadBuildFromCode(code)` 即可程序化导入。测试模式还会把这两个方法挂到 `window.__POB_TEST__`（`run.ts:134`）。

## 2. 换一件装备：接口怎么实现？

**当前没有「换装」接口。** 三条路：

**A. 整包重建（能用但重）**
自己拼出改了那件装备的构筑 XML（`SaveDB("code")` 格式），整体 `loadBuildFromCode` 重新导入。等于整 build 重来，无增量。

**B. 模拟 UI 输入（不推荐）**
用 `driverWorker` 的键盘/鼠标接口导航到装备格 → 开物品编辑器 → 粘贴新物品。极脆弱，升级即坏。

**C. 正解：扩一层桥接（推荐，改动小）**
照现有 `load_build_from_code` 模板加一个 C 导出函数 `set_item_in_slot(slot, itemXml)`：
1. `driver.c` 加 `EMSCRIPTEN_KEEPALIVE int set_item_in_slot(...)`，内部 `lua_getglobal(L, "setItemInSlot")` + `lua_pcall`（现有 `load_build_from_code` 在 `driver.c:585` 即此模板）；
2. `boot.lua` 加 Lua 全局 `setItemInSlot`，用已存在的 `GetMainObject()`（`driver.c:113`）拿到 `mainObject.main.modes["BUILD"]`，改其 `itemsTab` / `items` / `slots` 表；
3. `worker.ts` 的 `resolveImports` 加一行 `cwrap`，`driver.ts` 暴露 `setItemInSlot(...)`。

`GetMainObject` 已把内核对象挂成 Lua 全局（`driver.c:113`），这条路通且低风险。

> ⚠️ 别被 `sub.c` 的 `LaunchSubScript` 误导：它能在 Lua 跑任意脚本并回传结果（`sub.c:13`），但 `sub_start` 用 `luaL_newstate()` 建了**全新隔离的 Lua 状态**（`sub.c:220`），**访问不到已加载的 build（mainObject）**。只适合跑独立脚本（带 lcurl 联网），不能换装或读属性。

## 3. 换完能否快速对比、看出提升？

**当前没有「读属性」接口，无法直接对比数值。** `getBuildCode()` 只吐分享码，不吐计算结果。需补一个「读属性」桥接：

- 加 `get_build_stats()`：从 Lua 主状态读 `build.calcsTab` 输出（DPS、生命、EHP、抗性、护甲…），序列化为 JSON 回传。模式同 `get_build_code`（`boot.lua:225` 已演示如何访问 `modes["BUILD"]`）。
- 对比流程：
  1. `loadBuildFromCode(A)` → `getBuildStats()` 存快照 S1
  2. `setItemInSlot(武器, 新装备)` → `getBuildStats()` 存快照 S2
  3. 直接 `S2 - S1` 出 diff（DPS +12%、生命 -50 等）

属性读数完全可行——内核本已算好这些量，只是没暴露。

---

## 落地建议（顺序）

1. **导入**：已现成（`loadBuildFromCode`），可直接 JS 跑通。
2. **换装 + 对比**：给驱动加两个桥接函数 `set_item_in_slot` + `get_build_stats`，工作量小、风险低，样板在 `driver.c` / `boot.lua` 已完整。
3. **快速验证**：若只想先跑通流程，用方案 A（整包重建 + 两次 `getBuildCode` 做 XML diff），再决定要不要做方案 C 的精细桥接。

### 需新增的改动点
| 文件 | 改动 |
|---|---|
| `packages/driver/src/c/driver.c` | 新增 `EMSCRIPTEN_KEEPALIVE set_item_in_slot` / `get_build_stats`，参照 `load_build_from_code`（`driver.c:585`） |
| `packages/driver/boot.lua` | 新增 Lua 全局 `setItemInSlot` / `getBuildStats`，用 `GetMainObject()` 访问 `modes["BUILD"]` |
| `packages/driver/src/js/worker.ts` | `resolveImports`（`worker.ts:320`）加两行 `cwrap` |
| `packages/driver/src/js/driver.ts` | `Driver` 暴露 `setItemInSlot(...)` / `getBuildStats()` 方法 |
