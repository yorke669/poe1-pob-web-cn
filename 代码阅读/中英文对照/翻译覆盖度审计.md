# 翻译覆盖度审计（对照翻译测试）

**目标**：从上游 PoB 源码提取所有英文 runtime 文本，与 PoeCharm zh-rCN 语料做对照，找出**哪些没翻译**、**为什么没翻译**、**怎么修**。

**工具**：`tools/translate/audit-coverage.py`（两模式：`audit` 覆盖率、`translate` 单点 T() 模拟）

**数据基准**：upstream `v2.67.2` + PoeCharm zh-rCN 70 个 CSV / 66705 条独立 key。

## 冰锥地雷（IcicleMine）聚焦报告

```
$ uv run python tools/translate/audit-coverage.py audit --gem IcicleMine
```

| 字段 | 上游英文 | 语料翻译 | 结果 |
|---|---|---|---|
| `name` | "Icicle Mine" | "冰锥地雷" | **EXACT** ✅ |
| `description` | "Throws a mine that fires projectiles around it when detonated..." | — | **MISS** ❌ |
| stat `display_additional_projectile_per_2_mines_in_detonation_sequence` | "Fires an additional Projectile for every 2 prior Mines in Detonation Sequence" | "每 {0} 个按传爆序列引爆的地雷就发射一枚额外投射物" | **运行时应命中**（语料用 `{0}`，upstream 硬编码 `2`，boot.lua 归一化后命中） |
| 其它 16 条 stat text | 全部 | 全部 | **EXACT** ✅ |

### 冰锥地雷红框英文的根因

**红框整句 = `description` 字段 = `skills.desc` 来源的 1266 条 MISS 中的一条**。

- 上游英文：`Data/Skills/act_int.lua:10014` 的 `description` 字段
- PoE1 v2.67.2 全部 1269 条 gem description 在 zh-rCN 语料里**零覆盖**（PoeCharm 自己跑也不翻）
- 这**不是 boot.lua 的 bug**，是结构性缺口：boot.lua 修了也救不了，必须**手动补语料**才能翻

### 截图下面那条「每 2 个按传播序列引爆的地雷就发射一枚额外投射物 (Not supported in PoB yet)」

- 左半中文：语料 `statDescriptions.csv:22066` 有翻译，但 upstream v2.67.2 把 `{0}` 改成了硬编码 `2`，需要走 boot.lua 的 `templatiseNumbers` 回退才能命中——已修（2026-09-02 boot.lua 修改 B）
- 右半 `(Not supported in PoB yet)`：`Modules/Main.lua:117` 硬编码字符串，语料无对应 key——结构性缺口
- **截图里左半显示中文**说明 boot.lua 修复已生效；若仍显示英文，说明**服务器三步（pack/build/dev）没跑**

## 结构性缺口 vs 可修复缺口

### 结构性缺口（boot.lua 修了也没用，必须手动补语料）

| 来源 | 缺口 | 影响 |
|---|---|---|
| `skills.desc` | 1266 条 | 全部 gem description 不翻译 |
| `(Not supported in PoB yet)` | 1 条 | 所有不支持 stat 行尾的红色提示 |
| 部分 `skills.name`（怪物技能） | 101 条 | 召唤物/怪物技能名（用户不关心） |

### 可修复缺口（boot.lua 修复已能覆盖大部分）

| 来源 | 缺口 | boot.lua 修复 |
|---|---|---|
| `stat_text` 中硬编码数字 vs `{N}` | 1481 条 | `templatiseNumbers` 回退 |
| `stat_text` 中 alt 变体 | ~3000 条 | 暂无修复路径 |
| `display_label` 大写/带括号变体 | 106 条 SUBSTR | `fuzzyLabelTable` + `compareLine` 回退 |

## 行动建议（按优先级）

### A. 冰锥地雷红框 description 的修复路径

| 方案 | 成本 | 推荐度 |
|---|---|---|
| **A1**：保留英文 description（最简，主流本地化也保留） | 0 | ⭐⭐⭐ 通用方案 |
| **A2**：手动补冰锥地雷三个变体 description（Icicle Mine / of Fanning / of Sabotage） | 3 条 | ⭐⭐ 推荐 |
| **A3**：批量翻译全部 1266 条 description | 高 | ⭐ 长期 |

A2 的具体做法（确认采用后）：
1. 在 `Unsorted.lua`（或新建 `Gems_data_desc.lua`）补：
   ```lua
   ["Throws a mine that fires projectiles around it when detonated. These projectiles quickly dissipate as they travel, before disappearing."]
   = "投掷一颗地雷，引爆时向周围发射投射物。这些投射物飞行时会迅速消散，然后消失。"

   ["Throws a mine that fires projectiles at enemies when detonated. These projectiles quickly dissipate as they travel, before disappearing."]
   = "投掷一颗地雷，引爆时向敌人发射投射物。这些投射物飞行时会迅速消散，然后消失。"
   ```
2. 重 pack + 重 build + 重 dev

### B. 验证 boot.lua 已生效

1. 服务器 `cd /opt/poe/poe1-pob-web`
2. 跑三步：
   ```bash
   mise run pack --game poe1 --tag v2.67.2
   mise run driver:build
   mise run driver:dev --game poe1 --version v2.67.2 --build debug
   ```
3. 浏览器 DevTools console 看 `[translate] STAT-TEMPLATE` 日志
