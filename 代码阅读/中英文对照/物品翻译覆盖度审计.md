# 物品翻译覆盖度审计

**方法**：复用 `tools/translate/audit-coverage.py`（扩展 5 个物品 source），从上游 v2.67.2 提取物品相关英文，对照 PoeCharm zh-rCN 语料（70 CSV / 66705 key）。

**物品相关英文来源**：
- `Data/Bases/*.lua`：`itemBases["BaseName"] = { type="Body Armour", ... }`（基底名 + 类型）
- `Data/Uniques/**/*.lua`：`[[ ... ]]` 长字符串块（第1行=传奇名，第2行=基底名，含 `{variant:N}` 前缀）
- `Data/FlavourText.lua`：`text = { "..." }` 传奇风味文本

## 缺口分析

### 真缺口（需补语料）

| 来源 | 缺口 | 内容 |
|---|---|---|
| `base.name` | 56 条 | 带变体后缀的基底名（Talisman 变体 `Avian Twins Talisman (Cold-To-Fire)`、Two-Toned Boots 变体 `(Armour/Evasion)` 等）；少数 Tincture 基底名（Oakbranch/Prismatic/Ashbark Tincture） |
| `base.type` | 2 条 SUBSTR | `Graft`/`Tincture`（物品类型；语料里是其他含义的翻译，非物品类型独立翻译） |
| `unique.base` | 7 条 | `Primal Arrow Quiver`、3 个 Tincture 基底名、Two-Toned Boots 变体等（少量真缺失） |

### 结构性（PoE 设计通病，非 bug）

- **`flavour.text` 99.1% MISS**：传奇风味文本（诗意背景故事）官方中文客户端也保留英文，**不本地化**。与 gem description 不同——gem description 是功能性描述（应翻），flavour text 是文学性文本（PoE 官方选择不翻）。**建议保持英文**，符合官方本地化规范。

### 提取伪影（非真缺口）

- `unique.base` 的 2-3 条 MISS（`League: Heist`、`(5-10)% increased Reservation Efficiency of Skills`）来自 `Generated.lua` 异常 `[[ ]]` 块（第2行是 metadata 而非基底名），数量极少，不影响结论。

| 维度 | gem description | 物品名/类型 |
|---|---|---|
| 覆盖率 | 0%（1266/1269 MISS） | 95-99.8% |

**结论**：物品 tooltip 的主要显示文本（物品名、类型、传奇名）已高度本地化；剩余缺口是变体后缀名和 Tincture 类，影响极小。传奇风味文本按 PoE 官方惯例保留英文，无需处理。

## 物品词条（mod 文本）翻译

**结论：物品 tooltip 上用户看到的词条 = mod 的 stat 文本，来自 `stat_text` source（79.8% EXACT / 20.1% MISS），与技能/被动树共用同一套 `StatDescriptions`。**

### 两类文本的区别

| 文本 | 来源 | 在 tooltip 显示？ | 覆盖度 |
|---|---|---|---|
| **词条行**（`+12 to Strength`） | mod 的 `stat` → `StatDescriptions` text（`stat_text` source） | ✅ 显示（用户可见词条） | 79.8% EXACT / 20.1% MISS（templatiseNumbers 回退后实际 ~12% 真缺） |
| **词缀后缀名**（`of the Brute`） | mod 的 `affix` 字段（`mod.affix` source） | ❌ 不显示 | 14.7% EXACT / 64% MISS |

### 关键澄清

- `mod.affix`（`of the Brute` 等）是 mod 的**内部命名标签**，用于物品数据解析/匹配（`Classes/Item.lua:565` `modData.affix == modName` 把粘贴的物品文本行匹配回 mod；`Item.lua:777` crafting 解析 `{range:...}(.+)`）。
- `affix` 名**不渲染到 tooltip**——GGG 物品名里的 `Ring of the Brute` 是 GGG 客户端组合 affix+base 生成的命名，PoB 的 item tooltip 只显示 mod 的 stat 文本行（explicit/implicit）。
- 因此 `mod.affix` 14.7% 的极低覆盖度**不影响用户可见的词条翻译**，无需处理（与 flavour.text 同理，属内部/命名性文本）。

### 审计数据

- `mod.affix` 提取：遍历 `Data/*.lua`（30+ Mod 文件 + Enchantment*/Essence/Rares 等），去重 `affix = "..."`，共 2159 条。
  - EXACT 318（14.7%）/ SUBSTR 458（含大量语料误命中，如 `of Arakaali`→`暗影女皇 阿拉卡力之魂`）/ MISS 1383（64%）。
- `stat_text`（词条行）已在全局审计覆盖：22659 条，EXACT 18080（79.8%），MISS 4549（20.1%，其中 ~1481 可被 `templatiseNumbers` 回退命中）。

### 工具

```bash
uv run python tools/translate/audit-coverage.py audit --source mod.affix   # 词缀名（内部，不显示）
# stat_text 为全局共用，见全局审计：--source stat_text
```

## 暗金物品（unique）词条行审计（unique.mods）

新增 `unique.mods` source：提取 `Data/Uniques/**/*.lua` 每个 `[[ ]]` 块第 3 行起的 mod 行（剥离 `{tags:...}`/`{variant:...}` 前缀，跳过元数据行 League:/Source:/Requires Level/Implicits:/Variant:/Selected Alt Variant/Item Level:/`--` 注释，排除 `Special/Generated.lua` 程序生成变体文件），用对齐 boot.lua `T()` 路径的 `lookup_template`（resolveToTemplate 数值→`{N}` 占位符归一化）查语料。

### 结果（v2.67.2，total = 9385 条 mod 行）

| 模式 | EXACT | TEMPLATE | MISS | 命中率 |
|---|---|---|---|---|
| 当前 boot.lua 运行时（无去符号回退） | 1522 | 6063 | **1800** | 80.9% |
| 加去符号回退（修复后） | 1522 | 7645 | 218 | **97.7%** |

### 根因：前导 `+` 符号 bug（约 1645 条）

MISS 中约 1645 条是带前导 `+` 的词条，例如：
- `+(20-30)% to Fire Resistance` / `+(17-29)% to Chaos Resistance`
- `+(20-30) to Strength` / `+(20-30) to Dexterity`
- `+(50-70) to maximum Life` / `+(20-30)% to Quality of all Skill Gems`

GGG 对该类 stat 的 statText 定义为 `#% to Fire Resistance`（**不带 `+`**），PoeCharm 语料 key 也是 `{0}% to Fire Resistance`（无 `+`）。但 PoB 渲染物品 mod 时自动加 `+` 前缀（`+(20-30)% to Fire Resistance`），boot.lua 的 `resolveToTemplate`（`packages/driver/boot.lua:272`）把其归一化为 `+{0}% to Fire Resistance`，与 key `{0}%` **严格匹配失败** → 未翻译。

不一致来源：GGG 各 stat 定义是否自带 `+` 不同。部分 stat 的 statText **带 `+`**（如 `+#% to Global Critical Strike Multiplier`），其 key `+{0}%` 能命中（所以 `+45% to Global Critical Strike Multiplier` 已翻译）；而 `#% to Fire Resistance` 类 key 无 `+`，渲染带 `+` 后漏翻。

### 修复方案（boot.lua）

在 `T()` 的 resolveToTemplate 查表路径（`boot.lua` ~353 行 `if key:find("[%d%%%(]") then`）增加「去前导 `+`/`-` 回退」：

```lua
if key:find("[%d%%%(]") then
    local templ, values = resolveToTemplate(key)
    translated = translateTable[templ] or translateTableLower[templ:lower()]
    if not translated and templ:match("^[%+%-]") then
        local templ2 = templ:sub(2):match("^%s*(.-)%s*$")
        translated = translateTable[templ2] or translateTableLower[templ2:lower()]
    end
    if translated then
        local result = translated:gsub("{(%d)}", function(i)
            return values[tonumber(i) + 1] or ("{" .. i .. "}")
        end)
        -- ...（原有 return 逻辑）
    end
end
```

修复后覆盖 80.9% → 97.7%。剩余 218 MISS 多为非词条文本：`Upgrade: Upgrades to unique{...} via currency{...}`、`Sockets: W-W-W`、

`Talisman Tier: N`、`LevelReq: N`；及少量小众真缺 stat（如 `Adds 1 to (30-50) Lightning Damage to Attacks`、`Minions have +(6-10)% chance to Suppress Spell Damage`）。

> 注：改 `boot.lua` 必须重新编译 driver wasm（`driver-build.sh`）才生效，仅重启 dev server 不生效。
