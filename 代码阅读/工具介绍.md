# 工具链介绍

本项目用 [mise](https://mise.jdx.dev/) 统一管理所有命令行工具的版本。mise 可以理解为
**pyenv + nvm + sdkman + make 的合体**：既管「装哪个版本的工具」，也管「怎么跑项目的任务脚本」。

工具版本写在仓库根目录的 `mise.toml`，安装结果落在 mise 的数据目录，**不污染系统 `/usr/local` 或 Homebrew**。

## 安装位置速查

所有工具的根目录：

```
~/.local/share/mise/          # = $MISE_DATA_DIR（未设置 XDG_DATA_HOME 时的默认值）
├── installs/                 # 各工具各版本的实际安装位置 ⭐
├── downloads/                # 下载缓存（tar.gz 等），删了会重新下载
├── plugins/                  # 工具插件（如 emsdk 的 vfox 插件）
└── shims/                   # shim 目录（本项目用 mise run，不用 shim 模式）
```

mise 自身在：`~/.local/bin/mise`

命名规律：`installs/<工具名>/<版本>/`，工具名中的 `/` 和 `:` 会被替换成 `-`。

| 工具 | 版本 | 安装路径 |
|---|---|---|
| deno | 2.9.3 | `~/.local/share/mise/installs/deno/2.9.3/bin/deno` |
| emsdk | 6.0.6 | `~/.local/share/mise/installs/emsdk/6.0.6/` |
| cmake | 4.3.3 | `~/.local/share/mise/installs/cmake/4.3.3/cmake-4.3.3-macos-universal/CMake.app/Contents/bin/cmake` |
| ninja | 1.13.2 | `~/.local/share/mise/installs/ninja/1.13.2/ninja` |
| hk | 1.54.1 | `~/.local/share/mise/installs/hk/1.54.1/` |
| pkl | 0.31.0 | `~/.local/share/mise/installs/pkl/0.31.0/pkl` |
| actionlint | 1.7.12 | `~/.local/share/mise/installs/actionlint/1.7.12/` |
| shellcheck | 0.11.0 | `~/.local/share/mise/installs/shellcheck/0.11.0/shellcheck-v0.11.0/` |
| sentry-cli | 3.6.2 | `~/.local/share/mise/installs/sentry-cli/3.6.2/` |
| pinggy | 0.5.1 | `~/.local/share/mise/installs/github-pinggy-io-cli-js/0.5.1/` |
| auth0-cli | 1.32.0 | `~/.local/share/mise/installs/aqua-auth0-auth0-cli/1.32.0/` |

### 这些命令是怎么进入 PATH 的

mise **不写死 PATH**，而是在以下时机动态把上表的 bin 目录前置到 PATH 前面：

- 打开新终端时，`~/.zshrc` 里的 `eval "$(mise activate zsh)"` 生效
- 执行 `mise run <任务>` / `mise x -- <命令>` 时临时注入

所以如果直接 `which emsdk` 找不到，属于正常现象，用 `mise which emsdk` 查，或者始终通过
`mise run ...` 来跑任务。

## 一、核心构建链（动到就会影响能否跑起来）

### deno 2.9.3 — 项目主力运行时

**类比**：Node.js 的替代品，由 Node 原作者 Ryan Dahl 开发，原生支持 TypeScript、内置
formatter / linter / test runner / 任务 runner。

**在本项目的角色**（最重要，其余工具基本都是围绕它转）：

- 所有 TypeScript/TSX 代码的运行时（5 个 workspace：`packages/{dds,driver,game,packer,web}`）
- npm 依赖管理器：项目里**没有 package.json**，依赖写在 `deno.json` 的 `imports` 字段，
  用 `npm:` / `jsr:` 前缀声明，通过 `deno ci` 安装到 `node_modules`
- 任务执行器：`mise.toml` 里每个 `[tasks.xxx]` 的 `run` 几乎都是 `deno task ...`
- 构建工具链入口：Vite、Wrangler、Playwright、React Router 全都是 deno 拉起的 npm 包

**关键配置文件**：`deno.json`（workspace + 依赖 + fmt/lint 规则）、`deno.lock`（依赖锁）

### emsdk 6.0.6 — Emscripten SDK

**类比**：把 C 代码编译成 JVM 字节码的 javac —— 只不过这里的目标平台是 **WebAssembly**。
底层是 clang/LLVM，所以体积最大（约 1.7 GB+，安装最慢的那个就是它）。

**在本项目的角色**：本项目能在浏览器跑 PoB 的核心前提。它把 Lua 5.2 解释器和 C 桥接层
编译成 `.wasm` + `.mjs`，让**原封不动的 PoB Lua 代码**能在浏览器里执行。

**关键配置文件**：`packages/driver/CMakeLists.txt`

### cmake 4.3.3 — 构建系统生成器

**类比**：Maven / Gradle —— 描述「有哪些源文件、怎么编译、链接成什么」，
但它本身不编译，而是生成给 ninja 执行的构建脚本。

**在本项目的角色**：配合 Emscripten 的 toolchain 编译 `packages/driver` 的 C 代码
（`src/c/*.c`）以及 submodule 里的 Lua 源码（`vendor/lua`、`vendor/luautf8`），
最终产出 `driver.mjs` + `driver.wasm`。

**关键配置文件**：`packages/driver/CMakeLists.txt`

> 注意：`vendor/lua`、`vendor/luautf8` 是 git submodule，未初始化时目录为空，
> CMake 会 glob 不到源文件导致构建失败。`mise run setup` 会处理。

### ninja 1.13.2 — 构建执行器

**类比**：make 的现代替代品，只负责「按依赖图增量执行编译命令」，速度极快。
平时不用直接接触，CMake 会自动调用它。

## 二、代码质量 / Git Hooks

### hk 1.54.1 — Git Hooks 管理器

**类比**：Python 的 pre-commit、Java 项目里的 husky + lint-staged。

**在本项目的角色**：管理 `pre-commit` 钩子，commit 前自动跑一遍 lint 并**自动修复**
（`fix = true`），配合 `stash = "git"` 保证只检查暂存区的文件。

**关键配置文件**：`hk.pkl`（用 pkl 语言写的 hk 配置）

hk 里配置的 4 个检查步骤：

| 步骤 | 作用范围 | 命令 |
|---|---|---|
| `deno-fmt` | js/jsx/json/jsonc/md/mts/ts/tsx | `deno fmt` |
| `deno-lint` | js/jsx/mts/ts/tsx | `deno lint` |
| `deno-check` | js/jsx/mts/ts/tsx | `tools/tasks/check-files.ts`（类型检查） |
| `pkl` | `*.pkl` | `pkl eval` |
| `actionlint` | `.github/workflows/*` | actionlint |

### pkl 0.31.0 — 配置语言

**类比**：HCL（Terraform）、Jsonnet、或者带类型和继承的 YAML。
Apple 开源的配置语言，用于生成/校验结构化配置。

**在本项目的角色**：只用来写 `hk.pkl` 这一个文件（hk 官方的配置格式就是 pkl）。
日常开发基本不用碰，但 `hk.pkl` 的语法校验要用到它。

### actionlint 1.7.12 — GitHub Actions 静态检查

**类比**：给 CI YAML 做「编译期检查」—— 检查语法错误、无效的输入参数、
未定义的变量引用、shell 脚本潜在问题等。

**在本项目的角色**：检查 `.github/workflows/{build,check,sync-upstream}.yml`，
通过 hk 的 pre-commit 钩子自动运行。

### shellcheck 0.11.0 — Shell 脚本静态检查

**类比**：Shell 领域的 ESLint。

**在本项目的角色**：检查 shell 脚本的常见陷阱（未加引号的变量、错误的条件判断等）。
主要由 actionlint 内部调用来检查 workflow 里内联的 shell 脚本，一般不直接使用。

## 三、运维 / 发布 / 调试

### sentry-cli 3.6.2 — 错误监控上传工具

**类比**：把 Java 的 `.pdb`/符号表上传到崩溃分析平台。

**在本项目的角色**：部署时上传 **source map 和 Wasm 调试信息**到 Sentry，
让浏览器里捕获的 Wasm 崩溃堆栈能还原成 `driver.c` 里的函数名和行号。
没有它，线上报错只能看到一堆 wasm 内存地址。

**相关任务**：

```bash
mise run sentry:upload                        # 手动上传
mise run test:sentry:live                     # 本地验证符号化链路（需 SENTRY_LIVE_* 变量）
```

**相关代码**：`tools/sentry-upload/main.ts`

### pinggy 0.5.1 — 内网穿透

**类比**：ngrok / frp / 花生壳。

**在本项目的角色**：把本地 `web:dev` 开发服务器暴露成一个临时的公网 HTTPS 地址，
方便用 iPhone Safari 真机调试移动端 UI（PoB 有大量移动端适配的 overlay）。

**相关任务**：

```bash
mise run web:dev:public
```

> 安全提醒：Pinggy 生成的 URL 每次都变，且**无需鉴权即可公开访问**，
> 不要在里面输入 POESESSID 或私人 build code。

### auth0-cli 1.32.0 — Auth0 身份服务命令行

**类比**：管理 Okta / Keycloak 租户的 CLI。

**在本项目的角色**：管理 Auth0 的配置（登录、用户体系）。
站点的「Cloud 存档」功能依赖 Auth0 登录 —— 登录后 `Cloud` 文件夹出现，
存档存到 Cloudflare KV，可跨设备访问。

**相关代码**：`auth0/actions`（Auth0 的自定义 Actions 脚本）、`packages/web` 里的 Auth0 集成

## 四、不是 mise 管的，但项目也依赖

| 名称 | 说明 | 安装方式 |
|---|---|---|
| **Playwright** | 浏览器自动化，跑 E2E 测试和 MCP 视觉调试 | deno 管理的 npm 包；浏览器本体需 `mise run visual:setup` 下载到 Playwright 的 OS 缓存（不入库） |
| **Vite** | 前端构建/开发服务器 | deno 管理的 npm 包 |
| **Wrangler** | Cloudflare Pages/Workers 本地模拟与部署 | deno 管理的 npm 包 |
| **Xcode Command Line Tools** | macOS 的 C/C++ 工具链（clang、make 等） | **唯一需要手动安装的东西之一**：`xcode-select --install` |
| **git submodule** | `vendor/lua`、`vendor/luautf8` | `mise run setup` 自动初始化 |

## 五、常用命令速查

```bash
# 环境相关
mise run setup              # 首次克隆后：装工具 + deno ci + 初始化 submodule + 装 git hooks
mise ls                     # 列出已安装的工具和版本
mise which <tool>           # 某工具的可执行文件绝对路径
mise env                    # 查看 mise 注入了哪些环境变量（含完整 PATH）
mise tasks                  # 列出所有可用任务

# 日常开发
mise run check              # 快速检查：生成文件校验 + 静态检查 + driver 单元测试
mise run fix                # 自动修复格式和 lint 问题
mise run test               # 完整验证（含 Wasm 和 web 构建），提 PR 前必跑
mise run pack --game poe2 --tag v0.8.0   # 打包上游 PoB 资源（首次跑 dev 前必须做）
mise run driver:dev --game poe2 --version v0.8.0   # 只跑 driver 开发服务器
mise run web:dev            # 跑完整 web 应用开发服务器
mise run web:dev:public     # 通过 Pinggy 暴露到公网（真机调试）

# E2E / 视觉
mise run visual:setup       # 安装 Chromium / Firefox / WebKit
mise run test:e2e:driver    # 在真实浏览器里跑 driver 运行时测试
mise run test:e2e:web       # 跑 web 端到端关键路径测试
```

## 六、工具与项目文件的关系

```
mise.toml ──────────────► 定义所有工具版本（相当于 pom.xml 的 dependencyManagement）
  │
  ├─ deno ──────────────► deno.json（workspace + npm 依赖 + tasks）
  │                         └─ 拉起 Vite / Wrangler / Playwright / React Router
  │
  ├─ emsdk + cmake + ninja ─► packages/driver/CMakeLists.txt
  │                             └─ vendor/lua + vendor/luautf8 + src/c/*.c
  │                                 └─ 产出 driver.wasm / driver.mjs
  │
  ├─ hk ────────────────► hk.pkl（pre-commit 钩子定义）
  │     ├─ deno fmt / lint / check
  │     ├─ pkl eval（校验 hk.pkl 自身）
  │     └─ actionlint ──► .github/workflows/*.yml ─► 内联调用 shellcheck
  │
  ├─ sentry-cli ────────► tools/sentry-upload/main.ts（上传 source map + Wasm 调试信息）
  ├─ pinggy ────────────► tools/tasks/main.ts（web:dev:public 内网穿透）
  └─ auth0-cli ─────────► auth0/actions（登录与云存档的身份服务配置）
```
